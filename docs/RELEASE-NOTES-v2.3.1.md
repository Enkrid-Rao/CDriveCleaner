# CDriveCleaner v2.3.1

> 修复：归档带只读属性的 Junction 目录（Videos / Music / Pictures）会卡在最后一步。

## 这次的根因

v2.3.0 及更早版本在归档一个**已经是 Junction** 的目录时，流程是「删链接 → 删旧目标 → 重建链接」。
但旧版整理工具创建的链接自带 **ReadOnly** 属性，Windows 的 `RemoveDirectory` 对只读链接直接返回
`拒绝访问（5）`；而 `attrib -R` / `os.chmod` 都会跟随重解析点去改**目标**，永远清不掉链接自身的属性。

结果就是：数据已经复制并校验完，却在最后一步失败，原路径和 E 盘副本处于不一致状态。

## 修复

- **改指不再删除链接**：用 `FSCTL_SET_REPARSE_POINT` 就地改写重解析点。路径全程在线、不受只读属性影响，
  失败时原链接仍然可用；只有就地改指不可用时才回退到「删 + 建」。
- **删除统一走一个入口**：链接用 `OPEN_REPARSE_POINT` 句柄清自己的只读属性（不会误改目标），
  文件/目录先清只读再删，瞬时占用自动重试，失败返回真实 `WinError`。
- **归档顺序调整**：先改指、再清理旧目标；旧目标删不干净只记警告，不再把已经完成的归档记成失败。
- **预检只在需要时做**：只有「移动归档」（必须先删链接）才探测能否删除。

## 验证

- 49 项单元测试通过，新增 4 项：
  - 只读 Junction 就地改指
  - **Videos 场景的端到端回归**（只读 Junction 归档 → 改指成功、旧目标删除）
  - 只读文件删除
  - 占用时预检拦截
- 在 Windows 11 上对真实的 `Music` / `Pictures`（都是带只读属性的旧链接）做了空操作改指，均成功。
