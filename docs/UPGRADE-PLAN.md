# CDriveCleaner v2 重构与升级方案

> 状态：**已实现（v2.2.0）**（本文是 v2 的实施纲领；实际代码与验证记录见 PLAN.md / CHANGELOG.md）
>
> 目标：把「C 盘大目录 → D 盘 Junction」的单点工具，升级为
> **系统盘空间管理 + 冷数据归档**的一体化桌面应用，并彻底重做交互与视觉。

---

## 1. 为什么要重构

### 1.1 现状的三个硬伤

| 问题 | 现状 | 后果 |
|---|---|---|
| 空间模型不完整 | 只能把 C 盘目录搬到 D 盘 | 本机 C/D 是**同一块 1TB SSD** 的两个分区，搬来搬去总量不变；真正空闲的是 E 盘机械盘 |
| 安全链不够硬 | robocopy 退出码 + 文件数校验；删除用 `Remove-Item -Recurse` | 校验颗粒度粗；递归删除遇到 junction 有误删目标数据的风险；Junction 创建失败无自动回滚 |
| 交互密度太低 | 桌面 GUI 单页堆叠 + Web 版并存 | 扫描/迁移/撤销/日志混在一页；批量操作、失败恢复、历史回溯都缺；视觉陈旧 |

### 1.2 v2 的产品定位

> **一个把「C 盘空间」讲清楚、并把每一字节安全搬走的桌面工具。**

- **空间诊断**：三盘拓扑、C/D 同盘识别、可释放空间量化。
- **C 盘瘦身**：Junction 迁移（保留原路径），批量选择，可撤销。
- **冷数据归档**：按 IO 特征识别冷数据，迁移到指定机械盘；移动 / 链接 / 仅复制三种模式。
- **可恢复**：清单校验、操作审计、撤销/回迁、失败自动回滚。

## 2. 功能升级清单

### 2.1 C 盘瘦身（原有功能升级）

| 升级项 | v1 | v2 |
|---|---|---|
| 扫描 | PowerShell 逐目录递归，无进度、不可取消 | 原生扫描器 + 可选 Everything 后端；进度、取消、结果缓存 |
| 批量 | 一次只能点一个目录 | 多选 + 批量迁移 + 统一确认 |
| 校验 | 文件数 > 0 | 复制前后清单：路径 / 大小 / 文件数比对；不一致绝不删源 |
| 删除 | `Remove-Item -Recurse` | 自研安全删除：**永不递归进入 Junction/Symlink**，清只读，长路径 |
| 失败回滚 | 无 | Junction 创建失败 → 自动回拷 C 盘并校验；失败也会给出数据所在路径 |
| 权限 | 每个目录生成 .bat + 一次 UAC | 作业队列 + 自身提权 helper：一次 UAC 执行整批，GUI 实时读进度 |
| 进程占用 | 进程名模糊匹配 | Restart Manager 检测文件锁（更准），保留进程名兜底 |
| 链接管理 | 混在结果列表 | 独立页面：正常 / 目标缺失 / 机械盘目标；修复、撤销、打开 |
| 历史 | 只有文本日志 | `audit.jsonl` 结构化审计 + 历史页 + 撤销/回迁/导出 |

### 2.2 冷数据归档（新增）

- **目标盘识别**：枚举卷 → 分区 → 物理盘，标注 SSD / HDD / USB；默认推荐非系统机械盘。
- **冷数据识别**：按「IO 模式」而不是文件大小判断：
  - 视频、镜像、安装包、压缩归档、照片素材、长期未改的归档目录 → 推荐；
  - 浏览器缓存、聊天数据库、代码仓库 / node_modules（小文件随机 IO）→ 不推荐。
  - 输出推荐等级、理由、扩展名构成、最后修改时间。
- **三种归档模式**：
  1. **移动归档（默认）**：复制 → 校验 → 清空源内容，保留目录结构与空子目录。
  2. **链接归档**：复制 → 校验 → 清空源内容 → Junction 指回目标，程序仍可访问原路径（移动盘需谨慎）。
  3. **仅复制**：复制 → 校验，保留源目录（备份/暂存）。
- **自定义目录（可多选）**：冷数据推荐之外，可选择任意多个目录直接归档；按目录名同级放到目标路径。
- **已链接冷数据二次归档**：`C:\Users\...\Downloads` 已是 Junction 时，移动真实目标到机械盘，
  删除旧目标、把 C 盘链接改指到归档目标；C 盘路径保持不变。
- **安全**：目标空间预检、目标占用标记、清单校验、失败保留源、外置盘警告。
- **可回迁**：历史页对「移动归档」提供回迁（复制回源 → 校验 → 删目标）。

### 2.3 系统清理（轻量补充）

- Temp 清理：按保留天数、跳过占用文件、统计释放量。
- 回收站清空：需要显式确认，按盘清理。

### 2.4 UI 全面重做

- **信息架构**：侧边栏 6 个页面——总览 / C 盘瘦身 / 冷数据归档 / 链接管理 / 操作记录 / 设置。
- **设计语言**：深色玻璃 + 极光背景；C=珊瑚、D=紫、E=青 的存储语义色；
  JetBrains Mono 数字 + 微软雅黑中文；卡片化布局、统一 8pt 间距。
- **关键组件**：C 盘环形仪表、三盘拓扑、可动画数值卡、分段选择器、
  安全确认弹窗、全屏进度面板（阶段/百分比/速度/剩余时间/取消）、Toast。
- **交互**：批量选择、搜索、区域筛选、排序、键盘快捷键（Ctrl+1..6 / F5 / Ctrl+F）、
  空状态引导、骨架加载、减少动效开关。

## 3. 技术架构

```
cdc/
  core/
    models.py        # 数据模型（DriveInfo / ScanItem / Plan / OperationRecord / Progress）
    config.py        # v2 配置 + v1 兼容迁移
    windows.py       # PowerShell / robocopy / 磁盘 / Junction / 安全删除 / 文件锁
    safety.py        # 路径红线 / 空间预检 / 进程占用 / 目标标记
    scanner.py       # C 盘扫描 + 冷数据分析 + 缓存
    operations.py    # 迁移 / 撤销 / 归档 / 回迁 / 清理 / 审计
    jobs.py          # 提权作业协议（job/progress/result JSON）
  ui/
    theme.py icons.py widgets.py frameless.py dialogs.py state.py window.py
    pages/*.py
  app.py             # QApplication + 单实例 + CLI
```

### 3.1 作业协议（提权）

非管理员操作：QThread 内直接调用 core。
管理员操作：GUI 写 `job.json` → `ShellExecuteW("runas", 自身, "--elevated job.json")` →
helper 执行并写 `progress.json` / `result.json` → GUI 300ms 轮询。
一次 UAC 可执行整批；helper 崩溃时 GUI 能读到明确失败状态。

### 3.2 数据目录

| 运行方式 | 配置 / 日志 / 审计 |
|---|---|
| 安装版 | `%LOCALAPPDATA%\CDriveCleaner\` |
| 便携版（目录含 `portable.flag`） | `<程序目录>\data\` |
| 源码 | 仓库根目录（兼容旧 config.json） |

### 3.3 兼容

- 读取 v1 `config.json`（`target_base` / zones / threshold），自动升级为 v2 内存结构；
  首次保存时写 v2，并在 `data/backups/` 留旧配置副本。
- 已存在的 Junction 无需迁移，链接管理页直接识别；v1 创建的无标记链接撤销时默认保留目标副本。

## 4. 打包与分发

| 产物 | 方式 | 说明 |
|---|---|---|
| `CDriveCleaner-Setup-v2.2.0.exe` | Inno Setup 6 | 安装版：开始菜单 + 桌面快捷方式 + 卸载；默认当前用户安装，可选所有用户 |
| `CDriveCleaner-Portable-v2.2.0.zip` | PyInstaller onedir + `portable.flag` | 解压即用，配置/日志在 `data/`，可放 U 盘 |

- PyInstaller onedir（启动快、Qt 加载稳定），`--windowed`，带版本资源与图标。
- 构建脚本：`packaging/build.ps1`（清理 → 构建 → 便携包 → 安装包 → SHA256）。
- 未签名提醒：SmartScreen 可能提示，README 说明。
